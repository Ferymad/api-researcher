# Deep Researcher Agency - Product Requirements Document

## Overview
**Purpose**: Perform comprehensive API documentation research using multiple MCP servers to discover, evaluate, and document APIs, MCP servers, SDKs, and libraries.
**Target Users**: Agency builders who need detailed API documentation before creating Agency Swarm agencies.
**Key Value**: Replaces single-agent api-researcher with multi-source research capability, providing higher quality documentation with confidence scores and source citations.
**Agent Count Justification**: 16 total MCP tools requires minimum 2 agents (9-16 tools threshold). CEO orchestrates research strategy while Deep Researcher executes all searches using 5 MCP servers.

## Agency Configuration
- **Name**: deep_researcher (lowercase with underscores)
- **Pattern**: Orchestrator-Workers
- **Entry Agent**: CEO (receives user concept, coordinates research)

## Agents

### Agent 1: CEO (Entry Point)
- **Folder Name**: ceo (snake_case)
- **Instance Name**: ceo (snake_case)
- **Agent Name**: "CEO" (PascalCase in Agent() call)
- **Description**: Research orchestrator who receives user concepts, breaks down research into phases, delegates to Deep Researcher, and synthesizes final documentation
- **Primary Responsibilities**:
  1. Parse user concepts to identify research requirements (MCP servers, REST APIs, SDKs, libraries)
  2. Create research strategy following broad-to-narrow methodology (survey → evaluate → document)
  3. Delegate specific research tasks to Deep Researcher with clear search parameters
  4. Synthesize research results into structured output format
  5. Assess research quality, identify gaps, and request additional searches as needed
- **Tools** (0 MCP tools, built-in only):
  - Built-in: SendMessage (delegate to deep_researcher)
- **API Keys Required**: OPENAI_API_KEY

### Agent 2: Deep Researcher
- **Folder Name**: deep_researcher (snake_case)
- **Instance Name**: deep_researcher (snake_case)
- **Agent Name**: "Deep Researcher" (PascalCase in Agent() call)
- **Description**: Research execution specialist with access to 5 MCP servers for comprehensive API documentation gathering, evaluation, and extraction
- **Primary Responsibilities**:
  1. Execute web searches using Brave Search and Exa for API discovery
  2. Fetch GitHub repository documentation using DeepWiki
  3. Query library documentation using Context7 (33K+ libraries)
  4. Extract content from URLs using Jina AI reader
  5. Perform semantic searches and deep research with Exa
  6. Return structured results with confidence scores and source URLs
- **Tools** (16 total MCP tools):
  - MCP: DeepWiki → ask_question, read_wiki_structure, read_wiki_contents
  - MCP: Context7 → resolve-library-id, get-library-docs
  - MCP: Exa → web_search_exa, deep_search_exa, get_code_context_exa, crawling_exa, company_research_exa, research_paper_search, linkedin_search_exa
  - MCP: Jina AI → read_url, search
  - MCP: Brave Search → brave_web_search, brave_local_search
  - Built-in: SendMessage (return results to ceo)
- **API Keys Required**:
  - OPENAI_API_KEY (required)
  - EXA_API_KEY (required)
  - BRAVE_API_KEY (required)
  - CONTEXT7_API_KEY (optional, for private docs)
  - JINA_API_KEY (optional, increases rate limits)

## Workflow Examples

6. CEO delegates: "Get detailed documentation for the GitHub MCP server"

9. CEO synthesizes into api_docs/ structure:
   - readme.md: Overview with confidence score (High)

10. CEO presents to user: "Found 1 MCP server with 15 tools. Ready for PRD creation."

## Research Methodology

The CEO employs a **broad-to-narrow** research strategy:

1. **Survey Phase** (Broad):
   - Search for MCP servers first (preferred solution)
   - Search for official APIs and SDKs
   - Gather multiple options

2. **Evaluation Phase** (Narrow):
   - Assess maintenance status (last updated, active development)
   - Check documentation quality
   - Evaluate tool completeness
   - Compare alternatives

3. **Documentation Phase** (Deep):
   - Extract detailed documentation
   - Test example code validity
   - Identify integration requirements
   - Document limitations and costs

4. **Synthesis Phase** (Output):
   - Create structured documentation
   - Assign confidence scores
   - Provide clear recommendations
   - List all required API keys

## Confidence Scoring

**High Confidence**:
- Official MCP server or well-maintained third-party
- Active development (updated within 6 months)
- Complete documentation with examples
- Clear integration path

**Medium Confidence**:
- Working solution but limited maintenance
- Documentation exists but incomplete
- Some custom work required
- Unclear pricing or rate limits

**Low Confidence**:
- Deprecated or unmaintained
- Poor/missing documentation
- Significant custom development needed
- High uncertainty about implementation

## Design Decisions

### Why 2 Agents (Not 1)?
- 16 total tools exceeds 8-tool threshold for single agent
- Clear separation: strategy (CEO) vs. execution (Deep Researcher)
- CEO needs to synthesize results from multiple searches
- Better error handling with orchestrator reviewing execution results

### Why Not 3+ Agents?
- All research tools are complementary, not separate domains
- Splitting by MCP server would create artificial boundaries
- 16 tools fits comfortably in 2-agent architecture (9-16 range)
- Adding agents would increase complexity without benefit

### Why Orchestrator-Workers Pattern?
- CEO needs to control research strategy and phasing
- Deep Researcher executes but doesn't decide what to search
- No need for researcher-to-researcher collaboration
- Simple delegation model matches research workflow

### Why These Specific MCP Servers?
- **DeepWiki**: Best for GitHub repo documentation (free)
- **Context7**: Covers 33K+ library docs (free)
- **Exa**: Semantic search superior to keyword search (paid but essential)
- **Jina AI**: URL-to-markdown essential for extracting docs (mostly free)
- **Brave Search**: Baseline web search, required discovery phase (free tier)

### Why No Custom Tools?
- All research needs covered by MCP servers
- Custom tools would duplicate MCP functionality
- Maintenance burden: MCP servers updated by providers
- Integration: MCP servers already Agency Swarm compatible

## Replacement Strategy

This agency replaces the single `api-researcher` agent:

### Migration Path
1. Keep api-researcher agent until deep_researcher is tested
2. Test deep_researcher with same queries used by api-researcher
3. Compare output quality and completeness
4. Once validated, update orchestrator to call deep_researcher agency
5. Archive api-researcher agent

### Key Improvements Over Single Agent
- **Multi-source research**: 5 MCP servers vs. 1-2 tools
- **Better documentation**: Structured output with confidence scores
- **Semantic search**: Exa provides context-aware search vs. keyword only
- **Library coverage**: Context7 covers 33K+ libraries automatically
- **GitHub docs**: DeepWiki extracts repo documentation natively
- **Quality assessment**: CEO synthesizes and scores findings

### Backward Compatibility
- Output format (api_docs/) remains compatible with prd-creator
- readme.md includes same recommendation structure
- Can be drop-in replacement in existing workflows
